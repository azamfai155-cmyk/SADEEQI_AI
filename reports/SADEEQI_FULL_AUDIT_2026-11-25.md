## النتائج ذات الأولوية

### P0 — لا تعتمد إصداراً عاماً قبل إغلاقها
1. **تأكيد إعداد المصادقة الإنتاجي:** Worker وNode backend يستخدمان AUTH_MODE الافتراضي legacy في المصدر. يجب إثبات أن بيئة الإنتاج مضبوطة فعلياً على supabase، وأن الرموز القديمة لا تقبل، وأن اختبار sign-up/sign-in/refresh/expired-token يعمل. لا يمكن إثبات إعدادات Vercel/Cloudflare السرية من ملفات GitHub.
2. **مفاتيح الخدمة:** مدير المهام يستخدم SUPABASE_SERVICE_ROLE_KEY على الخادم. يجب التأكد من وجوده كسر خادم فقط، وعدم وجوده في APK أو browser bundle أو logs، مع RLS مفعّل على الجدول.
3. **ترحيل قاعدة البيانات:** PR #51 يتطلب تنفيذ supabase/migrations/202611180001_sadeeqi_tasks.sql يدوياً على المشروع الفعلي. لا يوجد دليل من GitHub وحده أن الترحيل نُفذ في Supabase production أو أن سياسات RLS اختُبرت هناك.
4. **مراجعة نتائج SAST:** Semgrep workflow يرفع التقرير لكنه لا يحوّل النتائج إلى بوابة منع إصدار. يجب مراجعة artifact 14985369937 وتصنيف كل finding ومعالجة ما هو حقيقي.

### P1 — إصلاحات تشغيلية وأمنية لازمة
5. **Rate limiting موزع:** المحدد الموجود داخل Node process ليس موزعاً، وWorker لا يملك محدداً مشتركاً مثبتاً. يلزم Cloudflare rate limiting/WAF أو Durable Object/مخزن مشترك، مع اختبارات تجاوز الحد عبر عدة instances.
6. **حماية URL/SSRF:** الفحص الحالي يرفض صيغاً محلية واضحة لكنه لا يثبت سلامة DNS/redirects أو عناوين IP النهائية. يجب منع الوصول إلى الشبكات الخاصة بعد DNS resolution وإعادة التحقق بعد كل redirect، أو استخدام fetch proxy مقيد.
7. **رفع الملفات:** فحص MIME والتوقيع لا يعادل مضاد فيروسات. يلزم عزل التخزين، حدود الحجم، فحص malware/quarantine، وموافقة قبل الحذف.
8. **قفل الاعتماديات:** لا يظهر package-lock.json ملتزم في مسار backend، وCI يولّد lockfile وقت التشغيل. يجب توليد lockfile ومراجعته والتزامه، ثم استخدام npm ci دون توليد ديناميكي.
9. **Guest session endpoint:** /v1/guest-session يتيح طلب إنشاء جلسة Supabase من دون مصادقة مسبقة. يلزم تقييد الميزة صراحةً، وحماية المعدل ومكافحة إساءة الاستخدام، وعدم تفعيلها ما لم تكن مطلوبة.
10. **تزامن المهام:** تخزين المهام يستخدم read-then-write دون optimistic concurrency/version check؛ قد تفقد تحديثات متزامنة. أضف version/updated_at شرطاً ذرياً واختبارات race.
11. **صلاحيات RLS:** سياسة migration لا تتضمن DELETE، وهذا مناسب كمنع حذف افتراضي، لكن يجب اختبار عزل مالك البيانات عملياً باستخدام JWT مستخدمين مختلفين، وعدم الاعتماد فقط على فلترة التطبيق مع service-role.
12. **حالة وكالة الوكلاء:** PR #53 يضيف roster وواجهة تصميمية؛ لا يثبت وجود orchestrator أو استدعاءات LLM منفصلة أو أدوات موصولة أو ذاكرة مشروع أو تنفيذ فعلي. يجب عرضها بوضوح كواجهة/تعريفات تجريبية حتى تنفيذ الخدمات.
13. **الاستيقاظ الصوتي:** عبارة «يا صديقي» وملف التدريب لا يثبتان نموذج wake-word مدرباً أو خدمة مستمرة موفرة للطاقة؛ يلزم نموذج فعلي واختبار false-accept/false-reject والبطارية والخصوصية.
14. **تحديث التطبيق:** يلزم endpoint إصدار رسمي، بصمة شهادة توقيع إنتاجية مثبتة، وتوقيع APK وإجراء تحديث/rollback مجرّب.

### P2 — إكمال الوظائف والمنتج

16. ربط أدوات البحث بمصادر فعلية مع citations، وتمييز بوضوح بين الوظائف المتصلة والمحاكاة.
