# SADEEQI AI — خطة تطوير النواة الذكية

هذه الخطة تفصل بين الكود الموجود والوظائف التي اجتازت الاختبار. لا تعني إضافة ملف أو زر أن الميزة أصبحت جاهزة للمستخدم.

## الوضع الحالي الذي تم فحصه

- Android: Kotlin + Jetpack Compose، Android SDK 35، minSdk 26.
- Backend: Node.js 20 + Express على Vercel.
- AI provider: اختيار Groq أو OpenAI من إعداد الخادم؛ المفاتيح تبقى في الخادم.
- Memory: Room + AES-GCM + Android Keystore، مع تصدير/استيراد مشفر. اختبار القبول موجود في androidTest لكنه يحتاج محاكي/هاتف.
- Voice: SpeechRecognizer + TextToSpeech في جلسة foreground بدأها المستخدم. لا يوجد wake-word دائم ولا full-duplex streaming.
- Music: Media3 + Audius، وليس كتالوجاً تجارياً شاملاً.
- Social: شاشة كتالوج حالة إعداد فقط؛ OAuth وربط الحسابات غير منفذين.
- PhoneControl: كان ملفه خارج source set الخاص بتطبيق Android وغير مربوط بالمحادثة.

## المرحلة 1 — تحكم الهاتف الآمن (بدأت)

- نقل وظائف Android إلى source set الصحيح.
- تحليل أوامر عربية محددة allow-list بدلاً من تخمين الأوامر.
- عرض مربع تأكيد قبل تنفيذ الأمر.
- تنفيذ فتح الكاميرا والإعدادات، رفع/خفض صوت الوسائط، فتح WhatsApp/Telegram/YouTube، وفتح محرر منبه Android.
- أوامر المنبه تفتح تطبيق الساعة؛ المستخدم يكمل الحفظ هناك.
- اختبار parser بوحدات JUnit.

## المرحلة 2 — Intelligence Core وTool Calling

- اعتماد عقد JSON موحد للأدوات: اسم الأداة، schema للمدخلات، مستوى الخطورة، هل تتطلب موافقة، ونتيجة التنفيذ.
- إضافة tool-calling من نموذج Groq Responses API، مع حلقة تنفيذ محدودة وعدد أقصى للخطوات.
- إبقاء الأدوات المحلية على Android؛ الخادم لا ينفذ أوامر الهاتف.
- إضافة أدوات البحث/الحساب/التاريخ/الذاكرة وفق مزود حقيقي ومفاتيح خدمة مضبوطة.
- منع النموذج من إصدار ادعاء نجاح قبل عودة نتيجة الأداة.
- سجل تدقيق للأوامر ونتائجها، مع حجب الأسرار.

## المرحلة 3 — الذاكرة الشخصية

- إكمال شاشة مراجعة الذكريات وتعديلها وحذفها.
- استخراج الذكريات بموافقة المستخدم، مع فصل الحقائق والتفضيلات والمشاريع والمهام.
- استرجاع الذاكرة ذات الصلة فقط مع كل محادثة.
- اختبارات ترحيل قاعدة البيانات، التشفير، النسخ الاحتياطي، واستعادة البيانات.

## المرحلة 4 — الصوت الطبيعي

- الإبقاء على SpeechRecognizer/TTS كخيار احتياطي يعمل على الجهاز.
- إضافة STT/TTS سحابي اختياري خلف الخادم بعد التحقق من السعر، اللهجات، والخصوصية.
- إضافة بث تدريجي للصوت/النص وإدارة المقاطعة.
- Wake word لا يعمل إلا عبر تنفيذ مستقل موفر للطاقة وموافقة واضحة؛ لا استماع خفي.

## المرحلة 5 — البحث والمعرفة والملفات

- بحث ويب بأداة حقيقية مع روابط ومصادر وتوقيت.
- قراءة PDF وDOCX وXLSX والصور عبر مسار رفع محدود الحجم ومتحقق من MIME.
- تحليل طبي تثقيفي مع تنبيه واضح بعدم التشخيص.
- عدم إرسال ملفات خاصة إلى مزود خارجي إلا بعد موافقة واضحة.

## المرحلة 6 — المنصات والخرائط والمهام

- OAuth مستقل لكل منصة، مع تخزين رموز الوصول المشفرة وتجديدها.
- بناء الوظائف فقط ضمن الصلاحيات الرسمية لكل منصة.
- خرائط وطقس وبيانات أرضية عبر مزودين محددين ومصادر مؤرخة.
- جدولة ومتابعة عبر WorkManager أو خادم مهام، مع تكرار آمن وتأكيد الإجراءات الحساسة.

## شروط قبول كل مرحلة

1. اختبارات وحدات ناجحة.
2. Android build ناجح وAPK artifact موجود.
3. اختبارات backend ناجحة.
4. اختبار على محاكي/هاتف حقيقي للوظائف المعتمدة على Android.
5. لا تُعرض ميزة كمتاحة إذا لم تكتمل مفاتيحها أو OAuth أو أذوناتها.
6. توثيق حدود الميزة، استهلاك الشبكة، والأذونات قبل التسليم.

## حدود معروفة حالياً

- لا يوجد wake word حقيقي أو استماع دائم.
- لا يوجد صوت full-duplex بزمن حقيقي.
- الحسابات الاجتماعية غير متصلة.
- لا توجد مكتبة موسيقى تجارية عالمية.
- لا يوجد قياس موثق للبطارية أو البيانات أو RAM حتى الآن.
- مفتاح تطبيق backend المضمّن في APK قابل للاستخراج؛ يجب استبدال المصادقة المشتركة بمصادقة مستخدم قصيرة العمر قبل الإصدار العام.
