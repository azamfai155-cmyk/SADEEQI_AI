# إعداد مصادقة صديقي بعد إزالة الرمز الثابت

## أسرار Cloudflare Worker المطلوبة

اضبط الأسرار من لوحة Cloudflare Worker > Settings > Variables and Secrets، ولا تضعها في Git أو APK:

- `OPENAI_API_KEY`: مفتاح مزود الذكاء الاصطناعي.
- `OPENAI_MODEL`: اسم النموذج المسموح به في حسابك.
- `SADEEQI_SESSION_SECRET`: سر عشوائي قوي لا يقل عن 32 حرفاً، ويُفضّل توليده عشوائياً بطول 64 بايت أو أكثر.

يمكن توليد سر محلياً بأمر:
```bash
openssl rand -base64 48
```
انسخ الناتج مباشرة إلى Secret باسم `SADEEQI_SESSION_SECRET`. لا ترسله في المحادثة ولا تحفظه في ملفات المستودع.

## آلية المصادقة

- يطلب التطبيق جلسة من `POST /v1/session`.
- يوقّع الخادم JWT باستخدام HMAC-SHA256، وتنتهي صلاحيته بعد 10 دقائق.
- يرسل التطبيق الرمز المؤقت إلى `POST /v1/chat` ولا يحفظه على الجهاز.
- لا يحتاج APK إلى مفتاح تطبيق ثابت أو مفتاح مزود الذكاء الاصطناعي.

## شرط قبل الإطلاق العام

نقطة إصدار الجلسات عامة بطبيعتها، ولذلك لا تعتبر هذه الآلية وحدها حماية كافية من إساءة الاستخدام أو استهلاك رصيد API. قبل إتاحة Worker للعامة، أنشئ Cloudflare Rate Limiting Rule لمساري `/v1/session` و`/v1/chat`، مع حدود منفصلة ومراقبة للطلبات، وفعّل تنبيهات الاستخدام وحدود الإنفاق لدى مزود الذكاء الاصطناعي. لا تعتمد على CORS كوسيلة مصادقة؛ تطبيقات الهاتف ليست مقيدة بسياسة CORS.

لا يوجد في هذا التغيير ربط Durable Objects أو KV لحدود موزعة داخل الكود؛ يجب إعداد قاعدة Cloudflare من لوحة التحكم والتحقق منها قبل النشر.

## التحقق

شغّل من جذر المستودع:
```bash
node --test worker.test.js
```
ثم:
```bash
gradle :app:assembleDebug
```

نجاح الاختبارات والبناء لا يثبت نشر Worker أو اختبار التطبيق على هاتف فعلي.
