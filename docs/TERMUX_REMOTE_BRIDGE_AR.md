# جسر Termux الآمن — تصميم وتنفيذ مرحلي

**الحالة:** مواصفة أولية، وليست برنامجاً جاهزاً أو اتصالاً مباشراً بـ ChatGPT.
**الفرع:** `feature/termux-bridge-foundation-2026-11-16`

## الهدف

تمكين المستخدم من تشغيل مهام تطوير محددة على جهاز Android داخل Termux، مع عرض الأمر والسبب والنتيجة، ومنع تنفيذ أوامر عامة غير موثوقة. يجب أن يبقى المستخدم قادراً على إيقاف الجسر ومراجعة كل مهمة.

## حقيقة الاتصال المهمة

هذه المواصفة لا تنشئ قناة تلقائية من محادثة ChatGPT الحالية إلى Termux. لا يستطيع خادم Termux المحلي استقبال اتصال من هذه المحادثة، ولا يتيح حساب ChatGPT Free إضافة موصل MCP مخصص. لذلك لا يجوز وصف النظام بأنه «ChatGPT يتحكم بالهاتف مباشرة».

يمكن استخدام المستودع وموصل GitHub المتاح لإعداد الملفات ومراجعتها، ويمكن لاحقاً تشغيل وكيل منفصل متصل بخدمة وسيطة إذا اختير مزود ونموذج مناسبين. هذا وكيل منفصل وليس هذه المحادثة.

## البنية المقترحة

```
مستخدم Android
  └─ Termux Bridge (عملية محلية يبدأها المستخدم)
       ├─ قائمة مهام مسموحة ومحددة
       ├─ تحقق من توقيع المهمة وانتهائها
       ├─ تنفيذ محلي محدود داخل مجلد المشروع
       └─ سجل نتائج منقح من الأسرار

خدمة وسيطة اختيارية (مرحلة لاحقة)
  ├─ مصادقة مستخدم مستقلة
  ├─ طابور مهام محدود العمر
  ├─ توقيع المهام ومنع إعادة التشغيل
  └─ واجهة نتائج
       └─ وكيل خارجي اختياري (ليس ChatGPT الحالي)
```

لا يُفتح منفذ Termux على الإنترنت، ولا يستخدم tunnel عام في الإصدار الأول.

## نموذج الأمان

1. **رفض افتراضي:** لا يقبل الجسر shell command حرّاً، ولا `eval`، ولا `sh -c`، ولا سلاسل أوامر.
2. **أدوات مسماة فقط:** كل عملية هي معرف ثابت مع مخطط مدخلات متحقق منه، مثل `git_status` أو `run_backend_tests`؛ لا يقبل نصاً يتحول إلى أمر.
3. **حدود المسار:** يحصر الوصول في جذر المشروع الحقيقي بعد حل symlinks، ويرفض المسارات المطلقة و`..` وأي خروج من الجذر.
4. **موافقة محلية:** لا تنفذ تغييرات ملفات أو Git push أو حذف أو نشر دون موافقة صريحة على الهاتف تعرض ملخص التغيير.
5. **لا أسرار:** لا يقرأ أو يطبع `.env` أو مفاتيح API أو مفاتيح SSH أو ملفات keystore أو بيانات المصادقة. لا يرسل محتويات الملفات تلقائياً إلى خدمة خارجية.
6. **توقيع ومهلة:** المهام البعيدة المستقبلية يجب أن تحمل nonce فريداً، ووقت انتهاء قصيراً، وتوقيعاً موثقاً؛ ترفض المهام المنتهية أو المكررة.
7. **حدود موارد:** مهلة تنفيذ، حد لحجم المخرجات، حد للعمليات المتزامنة، وإلغاء فعلي للعمليات طويلة التشغيل.
8. **تدقيق:** يسجل معرف الأداة ووقت البدء/النهاية ورمز الخروج، مع حجب الأسرار وعدم تخزين محتوى خاص افتراضياً.
9. **إيقاف آمن:** أمر إيقاف محلي يوقف استقبال المهام وينهي العمليات التابعة.
10. **عدم تصعيد الصلاحيات:** لا root ولا Accessibility automation ولا قراءة إشعارات/رسائل أو تحكم شامل بالجهاز.

## مراحل التنفيذ

### المرحلة A — المواصفة ومراجعة التوافق (هذه المرحلة)
- تثبيت حدود الثقة ونموذج الأمان.
- مراجعة إعدادات Node وAndroid الموجودة قبل إضافة خدمة.
- عدم تغيير المصادقة أو نشر أي خدمة.

### المرحلة B — أداة محلية بلا شبكة
- إنشاء حزمة Termux منفصلة لا تتصل بالإنترنت.
- إضافة أوامر قراءة فقط أولاً: حالة Git، فحص ملفات محددة، واختبارات backend.
- السماح بالتنفيذ داخل جذر المشروع فقط.
- اختبارات رفض المسارات والأوامر غير المسموحة والمهلات والمخرجات الضخمة.

### المرحلة C — موافقات التغيير
- إضافة أدوات كتابة محدودة مع عرض diff قبل التنفيذ.
- لا حذف جماعي، ولا `git reset --hard`، ولا `git clean`، ولا force push.
- إنشاء فرع منفصل لكل مهمة؛ لا تعديل `main` مباشرة.

### المرحلة D — قناة نتائج اختيارية
- تحديد وسيط موثوق ومتاح مجاناً قبل اختيار تقنية الاستضافة.
- لا تضاف قناة سحابية قبل إثبات المصادقة والتوقيع ومنع replay وعزل المستخدم.
- لا يدّعي الوسيط أنه ChatGPT؛ الوكيل الخارجي، إن وجد، مستقل.

### المرحلة E — قبول عملي
- اختبارات على نسخة تجريبية من مجلد المشروع.
- تحقق من أن الجسر لا يقرأ الأسرار ولا يخرج من مسار المشروع.
- اختبار انقطاع الشبكة، إلغاء المهمة، إعادة تشغيل الهاتف، وإيقاف الخدمة.
- لا إعلان عن نجاح التحكم قبل تنفيذ الاختبارات فعلياً على هاتف المستخدم.

## قيود بيئة المشروع المعروفة

- تطبيق Android الحالي لديه مصادقة Supabase وجلسات محلية مشفرة، لكن لا توجد خدمة Termux bridge مثبتة.
- backend الحالي يعمل على Vercel/Cloudflare بحسب مسارات النشر، ولا يثبت ذلك وجود قناة إلى عملية محلية على الهاتف.
- مستودع الهاتف قد يحتوي ملفات غير متتبعة وبيانات محلية؛ لا يجوز استخدام `git clean` أو `git reset --hard` أو `git add .` كخطوات إعداد.
- فرع الهاتف `recovery/phone-759429e` متأخر عن فرع التكامل؛ يجب عدم دمجه أو إعادة ضبطه قبل مزامنة واعية وحفظ أي عمل محلي.

## معيار الادعاء بالإنجاز

تعتبر المرحلة منجزة فقط عندما تكون الملفات موجودة، والاختبارات قابلة لإعادة التشغيل وناجحة، ويثبت تشغيلها على Termux. وجود هذه الوثيقة أو نجاح commit لا يثبت أن الجسر يعمل.
