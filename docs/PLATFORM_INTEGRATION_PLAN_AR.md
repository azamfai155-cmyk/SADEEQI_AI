# خطة دمج GitHub + Vercel + Cloudflare — SADEEQI AI

## الهدف
استخدام المنصات الثلاث مع إبقاء مصدر الحقيقة للكود في GitHub، وعدم تعطيل الخدمة الخلفية الحالية أثناء إدخال Cloudflare تدريجياً.

## توزيع المسؤوليات
- **GitHub:** المستودع، الفروع، مراجعة التغييرات، GitHub Actions، وسجل الإصدارات.
- **Vercel:** يستمر حالياً في استضافة واجهة/خلفية SADEEQI الحالية كما هي. لا ننقل أي endpoint إنتاجي قبل اختبار مكافئ على بيئة معاينة.
- **Cloudflare:** يضاف تدريجياً للخدمات الطرفية/المساندة (مثل Worker أو حماية/توجيه API) بعد ربط الحساب واختبار حدود الخطة المجانية. لا تُنقل الأسرار إلى المستودع أو تطبيق Android.

## ما تحقق في فحص 2026-11-16
- توجد ثلاثة مشاريع Vercel بأسماء `sadeeqi-ai` و`sadeeqi-ai-pdrk` و`sadeeqi-ai-kh3l`.
- المشروع `sadeeqi-ai-pdrk` لديه معاينة READY على فرع `feature/termux-bridge-foundation-2026-11-16`، للالتزام `c5030b965bc98e8514e982d402a6bca539b1f996`.
- آخر نشر معروف للمشروعين `sadeeqi-ai` و`sadeeqi-ai-kh3l` كان CANCELED. هذا لا يثبت أن كل نطاقاتهما متوقفة؛ يلزم فحص endpoint الإنتاجي بشكل مستقل.
- لم يتم التحقق من ربط Cloudflare أو تفويض حسابه بعد.

## ضوابط قبل أي تغيير
1. لا نحذف ولا نعيد تسمية أي مشروع Vercel من المشاريع الثلاثة قبل تحديد النطاق الإنتاجي المعتمد.
2. لا نغيّر متغيرات البيئة ولا نقرأ أو ننسخ قيم الأسرار ضمن هذه الخطة.
3. لا نضع مفاتيح OpenAI/Groq/Supabase service-role أو رموز النشر في Git.
4. يبقى Vercel backend الحالي هو المسار الأساسي حتى نجاح اختبارات Cloudflare المكافئة.
5. أي تحويل للمرور يكون تدريجياً مع إمكانية الرجوع إلى Vercel.

## مراحل التنفيذ
1. تثبيت خط الأساس: تحديد Vercel project/domain المعتمد، وفحص health endpoint وبيئة المعاينة.
2. ربط Cloudflare بتفويض مالك الحساب، ثم إنشاء Worker تجريبي غير متصل بمرور الإنتاج.
3. إضافة اختبارات عقد API بين تطبيق Android والخلفية، واختبارات health/auth/error.
4. تجربة Cloudflare Worker على مسار تجريبي فقط، دون أسرار أو بيانات مستخدمين حقيقية.
5. مقارنة النتائج والكمون والأخطاء، ثم اقتراح تحويل مسار واحد فقط بعد موافقة المالك.
6. توثيق إعدادات GitHub Actions وVercel وCloudflare، مع إبقاء الأسرار في مخازن الأسرار الخاصة بكل منصة.

## ما يحتاج إجراءً من المالك
- تفويض Cloudflare من لوحة الحساب أو تنفيذ خطوات الربط بنفسه؛ لا ترسل أي كلمة مرور أو API token في المحادثة.
- تأكيد النطاق الذي يستخدمه تطبيق Android حالياً قبل تغيير أي إعداد إنتاجي.
