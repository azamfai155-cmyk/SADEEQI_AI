# SADEEQI Termux Bridge — المرحلة الأولى

هذه أداة CLI محلية تجريبية، وليست خدمة تعمل في الخلفية.

## المتطلبات
- Termux مثبت من مصدر موثوق.
- Node.js متاح عبر Termux.
- نسخة المشروع موجودة في مجلدها المعتاد.

## التشغيل من جذر المستودع

```sh
node termux-bridge/bridge.mjs git_status
node termux-bridge/bridge.mjs backend_tests
```

الأداة لا تحتاج إلى تثبيت حزم npm إضافية.

## الأدوات المسموحة حالياً

| المعرف | الوظيفة | الأثر |
|---|---|---|
| `git_status` | `git status --short --branch` | قراءة حالة Git فقط |
| `backend_tests` | `npm test` | يتطلب موافقة محلية تفاعلية قبل التشغيل؛ قد ينشئ الاختبار ملفات مؤقتة |

أي اسم آخر مرفوض. لا تقبل الأداة أوامر shell أو معاملات يحددها المستخدم، وتستخدم `spawn` مع `shell: false`، ومجلد عمل ثابت، وبيئة متغيرات محدودة، ومهلة تنفيذ وحد أقصى للمخرجات. عند انتهاء المهلة أو تجاوز حد المخرجات، ترسل `SIGTERM` إلى مجموعة العملية ثم تصعّد إلى `SIGKILL` بعد 3 ثوانٍ إذا لزم الأمر.

## نظام الموافقة المحلي\n\nمهمة `backend_tests` لا تعمل إلا من جلسة Termux تفاعلية. تعرض الأداة اسم المهمة وتطلب كتابة العبارة المطابقة حرفياً: `أوافق على تشغيل المهمة: backend_tests`. الموافقة تخص هذه المهمة فقط، ولا تُخزّن ولا تمنح إذناً دائماً. عند التشغيل غير التفاعلي أو إدخال عبارة مختلفة، تُرفض المهمة. لا توجد وسيلة لتجاوز ذلك عبر معاملات سطر الأوامر.\n\n## ما لا تفعله الأداة

- لا تفتح منفذ شبكة ولا تنشئ HTTP server.
- لا تتصل بـ ChatGPT أو بأي خدمة وسيطة.
- لا تنفذ git add/commit/push/merge أو حذفاً أو كتابة ملفات.
- لا تقرأ ملفات الأسرار أو مفاتيح SSH أو keystore.
- لا تمنح صلاحيات root ولا تتحكم بواجهة Android.

## فحص يدوي قبل التشغيل

اقرأ الملف `bridge.mjs` قبل تشغيله. تأكد من أنك داخل نسخة المستودع الصحيحة، ولا تشغّل الأداة من مجلد مشروع لا تثق بمحتواه. مخرجات الاختبارات قد تتضمن معلومات من سجلات الاختبار؛ راجعها قبل مشاركتها.

## الخطوة التالية

اختبار نظام الموافقة على Termux نفسه، ثم دراسة واجهة أوامر محلية أكثر سهولة. لا تضف اتصالاً بعيداً أو نفقاً عاماً في هذه المرحلة.
